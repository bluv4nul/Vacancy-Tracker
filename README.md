# Vacancy Tracker

> В разработке

Веб-приложение для поиска стажировок и вакансий разработчика и учёта откликов.

Стажировки и вакансии разбросаны по hh.ru, сайтам крупных компаний и каналам в соцсетях. Vacancy Tracker собирает их в одном месте: вакансии с hh.ru подтягиваются автоматически по сохранённым поискам, остальные добавляются вручную. Внутри — исключение по словам, скрытие компаний, статусы откликов и уведомления о новых вакансиях в Telegram.

## Возможности (MVP)

- Сохранённые поиски по hh.ru с фоновой проверкой новых вакансий
- Поиск по словам: режим «все слова» / «любое слово» и слова-исключения
- Лента новых непросмотренных вакансий без дублей
- Ручное добавление вакансий из других источников
- Статусы откликов: интересно → откликнулся → тестовое → собес → оффер / отказ
- Скрытие компаний и заметки по вакансиям
- Уведомления в Telegram

## Стек

- JavaScript, Node.js, Express
- PostgreSQL, Prisma ORM 7 (драйвер-адаптер `@prisma/adapter-pg`)

## Запуск
Для запуска нужны установленные Docker и Node.js 22.18 или новее (либо 24+). Более старые версии не подходят: клиент Prisma генерируется в файлы `.ts`, и Node запускает их без дополнительных флагов только начиная с этих версий.

В корне репозитория лежит файл `.env.example`. По его образцу следует создать `.env` локально, указав свой пароль. Пароль указывается дважды — в `POSTGRES_PASSWORD` (для контейнера с базой) и внутри строки подключения `DATABASE_URL` (для приложения и Prisma), значения должны совпадать. Если в пароле есть спецсимволы (`@`, `:`, `/`, `#` и т. п.), в `DATABASE_URL` их нужно записать в URL-кодировке (например, `@` → `%40`).

> Не забудьте сохранить `.env`. С пустым файлом контейнер с базой не стартует (нет `POSTGRES_PASSWORD`), а `docker compose up -d` об этом не сообщит — проверяйте `docker compose ps`. Prisma в этом случае выдаёт ошибку `datasource.url property is required`.

Далее база данных поднимается в docker командой

```bash
docker compose up -d
```

Переменные `POSTGRES_*` действуют только при первом запуске на пустом томе: если поменять их позже, существующая база не изменится.

Затем установите зависимости и сгенерируйте клиент Prisma (он появится в `src/generated/prisma` и в репозиторий не входит):

```bash
npm install
npx prisma generate
```

Примените миграции — они создадут таблицы. `migrate deploy` только выполняет готовые миграции из `prisma/migrations` и ничего не генерирует, поэтому подходит для разворачивания базы:

```bash
npx prisma migrate deploy
```

После миграции добавьте тестового пользователя для разработки. Пока нет входа, приложение работает от его имени (`id = 1`), поэтому без этого шага функции API работать не будут. Повторный запуск ничего не меняет.

```bash
npx prisma db seed
```

Запустите сервер:

```bash
npm start
```

Сервер запустится на http://localhost:3000. Проверить, что он видит базу, можно по адресу http://localhost:3000/health — в ответе будет текущее время из PostgreSQL.

Чтобы посмотреть таблицы напрямую, войдите в базу данных:

```bash
docker compose exec db psql -U vacancytracker -d vacancytracker
```

Внутри `psql` результат можно проверить двумя командами: `\dt` выводит список таблиц, `\d <имя_таблицы>` — устройство одной таблицы. Выход — `\q`.

```
\dt
\d users
```

## API

Пока все запросы выполняются от имени тестового пользователя (`id = 1`), вход появится позже. Тело запросов и ответов — JSON, имена полей в camelCase.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/health` | Проверка связи с базой: текущее время из PostgreSQL |
| `GET` | `/vacancies` | Ручные вакансии текущего пользователя, новые первыми |
| `POST` | `/vacancies` | Добавить ручную вакансию |
| `PATCH` | `/vacancies/:id` | Изменить статус отклика, заметку или отметку «просмотрено» |
| `GET` | `/searches` | Получить сохранённые поиски текущего пользователя |
| `POST` | `/searches` | Создать сохранённый поиск |
| `PATCH` | `/searches/:id` | Изменить настройки сохранённого поиска |
| `DELETE` | `/searches/:id` | Удалить сохранённый поиск |

### `GET /vacancies`

Вместе с полями вакансии в каждой записи приходят данные текущего пользователя по ней: `status`, `note`, `isViewed`, `statusChangedAt`. Если вакансию ещё не меняли через `PATCH`, у неё `status`, `note` и `statusChangedAt` равны `null`, а `isViewed` — `false`.

### `POST /vacancies`

Обязательные поля — `companyName`, `title`, `url`, остальные можно не передавать. Компания ищется по названию без учёта регистра и пробелов по краям; если такой ещё нет, она создаётся.

```json
{
  "companyName": "Яндекс",
  "title": "Junior Backend Developer",
  "url": "https://example.com/vacancy/1",
  "city": "Москва",
  "salaryFrom": 80000,
  "salaryTo": 120000,
  "currency": "RUB",
  "experience": "noExperience",
  "schedule": "remote",
  "description": "Node.js, PostgreSQL, Express",
  "publishedAt": "2026-10-15T10:00:00Z"
}
```

Ответы:

- `201` — вакансия создана, в ответе она целиком, вместе с `id`;
- `400` — не хватает обязательного поля, вакансия не создаётся.

### `PATCH /vacancies/:id`

Меняет данные текущего пользователя по вакансии. Все поля необязательны, но хотя бы одно должно быть передано:

- `status` — статус отклика, одно из значений: `interested`, `applied`, `test_task`, `interview`, `offer`, `rejected`, `withdrawn`, `skipped`;
- `note` — заметка, строка;
- `isViewed` — просмотрена ли вакансия, `true` или `false`.

Поле, которое не передано или передано как `null`, не меняется. Чтобы удалить заметку, передайте пустую строку: `"note": ""`. При смене статуса обновляется `statusChangedAt`.

```json
{
  "status": "applied",
  "note": "Откликнулся через сайт компании"
}
```

Ответы:

- `200` — данные сохранены, в ответе `userId`, `vacancyId`, `status`, `note`, `isViewed`, `statusChangedAt`;
- `400` — не передано ни одного поля, неизвестный статус или поле не того типа;
- `404` — вакансии с таким `id` нет или она принадлежит другому пользователю.

### `GET /searches`

Возвращает `200` и массив поисков текущего пользователя, включая выключенные. Поиски отсортированы по дате создания, от новых к старым.

### `POST /searches`

Обязательно только `name`. Остальные поля можно пропустить.

| Поле | Допустимые значения | По умолчанию |
|---|---|---|
| `name` | Строка, в которой есть хотя бы один непробельный символ | Обязательное поле |
| `includeWords`, `excludeWords` | Массивы строк | `[]` |
| `mode` | `all_words` («все слова») или `any_word` («любое слово») | `all_words` |
| `isActive` | `true` или `false` | `true` |
| `city`, `experience` | Строка или `null` | `null` |

- `201` — поиск создан, в ответе вся запись, включая `id`.
- `400` — тело запроса отсутствует, имя пропущено или значение поля некорректно.

### `PATCH /searches/:id`

Принимает те же поля, что и `POST`. Все поля необязательны. Если поле пропущено или передано как `null`, его значение сохраняется. Чтобы очистить `city` или `experience`, передайте `""`, а чтобы убрать все слова из списка, передайте `[]` для нужного поля. Пустой объект `{}` возвращает текущую запись.

```json
{
  "city": "",
  "isActive": false
}
```

- `200` — в ответе вся запись с обновлёнными значениями.
- `400` — передано некорректное значение поля.
- `404` — `id` некорректен, поиск отсутствует или принадлежит другому пользователю.

### `DELETE /searches/:id`

- `204` — поиск удалён, тело ответа пустое.
- `404` — `id` некорректен, поиск отсутствует или принадлежит другому пользователю.
