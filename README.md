# Vacancy Tracker

> В разработке

Веб-приложение для поиска стажировок и вакансий разработчика и учёта откликов.

Стажировки и вакансии разбросаны по hh.ru, сайтам крупных компаний и каналам в соцсетях. Vacancy Tracker собирает их в одном месте: вакансии с hh.ru подтягиваются автоматически по сохранённым поискам, остальные добавляются вручную. Внутри — исключение по словам, скрытие компаний, статусы откликов и уведомления о новых вакансиях в Telegram.

## Возможности (MVP)

- Сохранённые поиски по hh.ru с фоновой проверкой новых вакансий
- Поиск по словам: режим «все слова» / «любое слово» и слова-исключения
- Лента новых непросмотренных вакансий без дублей
- Ручное добавление вакансий из других источников
- Статусы откликов: интересно → откликнулся → тестовое → собес → оффер / отказ
- Скрытие компаний и заметки по вакансиям
- Уведомления в Telegram

## Стек

- JavaScript, Node.js, Express
- PostgreSQL (драйвер `pg`, сырой SQL)

## Запуск
Для запуска нужны установленные Docker и Node.js 20.6 или новее.

В корне репозитория лежит файл `.env.example`. По его образцу следует создать `.env` локально, указав свой пароль. Пароль указывается дважды — в `POSTGRES_PASSWORD` (для контейнера с базой) и в `PGPASSWORD` (для приложения), значения должны совпадать.

Далее база данных поднимается в docker командой

```bash
docker compose up -d
```

После поднятия базы данных необходимо выполнить миграцию для создания таблиц

Windows
```powershell
Get-Content .\migrations\001_init.sql | docker compose exec -T db psql -U vacancytracker -d vacancytracker
```

Mac/Linux
```bash
docker compose exec -T db psql -U vacancytracker -d vacancytracker < migrations/001_init.sql
```

После миграции добавьте тестового пользователя для разработки. Пока нет входа, приложение работает от его имени (`id = 1`), поэтому без этого шага функции API работать не будут.

Windows
```powershell
Get-Content .\seeds\001_dev_user.sql | docker compose exec -T db psql -U vacancytracker -d vacancytracker
```

Mac/Linux
```bash
docker compose exec -T db psql -U vacancytracker -d vacancytracker < seeds/001_dev_user.sql
```

Затем установите зависимости и запустите сервер:

```bash
npm install
npm start
```

Сервер запустится на http://localhost:3000. Проверить, что он видит базу, можно по адресу http://localhost:3000/health — в ответе будет текущее время из PostgreSQL.

Чтобы посмотреть таблицы напрямую, войдите в базу данных:

```bash
docker compose exec db psql -U vacancytracker -d vacancytracker
```

Внутри `psql` результат можно проверить двумя командами: `\dt` выводит список таблиц, `\d <имя_таблицы>` — устройство одной таблицы. Выход — `\q`.

```
\dt
\d users
```

## API

Пока все запросы выполняются от имени тестового пользователя (`id = 1`), вход появится позже. Тело запросов и ответов — JSON, имена полей в camelCase.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/health` | Проверка связи с базой: текущее время из PostgreSQL |
| `GET` | `/vacancies` | Ручные вакансии текущего пользователя, новые первыми |
| `POST` | `/vacancies` | Добавить ручную вакансию |
| `PATCH` | `/vacancies/:id` | Изменить статус отклика, заметку или отметку «просмотрено» |

### `GET /vacancies`

Вместе с полями вакансии в каждой записи приходят данные текущего пользователя по ней: `status`, `note`, `isViewed`, `statusChangedAt`. Если вакансию ещё не меняли через `PATCH`, у неё `status`, `note` и `statusChangedAt` равны `null`, а `isViewed` — `false`.

### `POST /vacancies`

Обязательные поля — `companyName`, `title`, `url`, остальные можно не передавать. Компания ищется по названию без учёта регистра и пробелов по краям; если такой ещё нет, она создаётся.

```json
{
  "companyName": "Яндекс",
  "title": "Junior Backend Developer",
  "url": "https://example.com/vacancy/1",
  "city": "Москва",
  "salaryFrom": 80000,
  "salaryTo": 120000,
  "currency": "RUB",
  "experience": "noExperience",
  "schedule": "remote",
  "description": "Node.js, PostgreSQL, Express",
  "publishedAt": "2026-10-15T10:00:00Z"
}
```

Ответы:

- `201` — вакансия создана, в ответе она целиком, вместе с `id`;
- `400` — не хватает обязательного поля, вакансия не создаётся.

### `PATCH /vacancies/:id`

Меняет данные текущего пользователя по вакансии. Все поля необязательны, но хотя бы одно должно быть передано:

- `status` — статус отклика, одно из значений: `interested`, `applied`, `test_task`, `interview`, `offer`, `rejected`, `withdrawn`, `skipped`;
- `note` — заметка, строка;
- `isViewed` — просмотрена ли вакансия, `true` или `false`.

Поле, которое не передано или передано как `null`, не меняется. Чтобы удалить заметку, передайте пустую строку: `"note": ""`. При смене статуса обновляется `statusChangedAt`.

```json
{
  "status": "applied",
  "note": "Откликнулся через сайт компании"
}
```

Ответы:

- `200` — данные сохранены, в ответе `userId`, `vacancyId`, `status`, `note`, `isViewed`, `statusChangedAt`;
- `400` — не передано ни одного поля, неизвестный статус или поле не того типа;
- `404` — вакансии с таким `id` нет или она принадлежит другому пользователю.
